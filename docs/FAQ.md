# 常见问题

**简体中文** · [English](FAQ.en.md) · [文档目录](README.md)

## 要先把 Bot 叫进语音频道吗？

不需要。你先进入普通语音频道，再打开 Activity 点歌；首次需要播放时会连接 Bot。Bot 仍需拥有查看频道、连接和发言权限。只听歌的成员不必打开 Activity。

## 可以同时给多个频道播放吗？

同一个 Bot 在同一服务器内同时服务一个语音频道。各频道的房间和歌单独立，其他频道不能抢占当前语音连接。这个限制与播放列表数量无关。

## Activity 一直“正在连接”、黑屏或提示 JSON 错误

先检查桌面端的 Discord、本地网页和公网 HTTPS 状态，再按 [配置指南](CONFIGURATION.md) 核对 URL Mapping 与 OAuth 设置。

- 从所在服务器的普通语音频道打开 Activity，直接在浏览器访问网页不能替代 Discord 频道上下文。
- 确认 HTTPS 入口确实转发到当前 Bot 的网页端口，而不是默认站点、代理错误页或已失效隧道。
- `Unexpected token '<'` 往往表示 API 请求收到 HTML 页面；先查反向代理和转发路径。
- 检查域名、证书、监听地址和服务器转发配置后，重新打开 Activity。

SSH 是否免密码不是 Activity 登录的直接条件。应用管理 SSH 时需要专用密钥；如果 HTTPS 隧道本身已通，应继续查 Discord 授权配置。

## `oauth-exchange-401` 或缺少 `redirect_uri`

检查 Application ID、Bot Token、Client Secret 是否来自同一个 Discord 应用；重新填写已失效的 Client Secret。按桌面页面显示的 OAuth2 Redirect URI 在 Developer Portal 登记，并确认已启用 Activities 及测试访问权限。不要把这些凭据贴到 Issue。

## 浏览器能播，Bot 却无法播放

浏览器的 Cookie 不会自动同步。根据需要导入对应平台登录文件，并检查内容是否有账号、会员或地区限制。搜索结果可见也不保证可播放。检查「工具库」中的验证状态，更新工具后重新检查并重启 Bot。

`cache-download` 表示准备音频时失败，可能涉及来源请求、登录、网络、工具或磁盘；仅凭这个代码不能断定是 Cookie 错误。反馈时提供平台链接、应用版本和界面提示即可。

## 合集少了曲目，或无法读完

合集成员受来源接口及访问权限影响。先尝试当前单首，再检查合集是否公开可访问；重新识别可能得到不同结果。Bilibili 多 P 与视频合集是两种结构，均支持识别；网易云整张歌单批量导入目前不支持。已导入集合不会自动跟随来源更新。

## 为什么关闭点歌台后磁盘还有音频？

房间歌单和磁盘缓存是两件事。房间结束会清理房间状态；音频缓存按容量和最近使用情况保留以便复用，默认上限 1024 MiB，正在使用的文件受保护。停止 Bot 后可在「缓存与诊断」清理。它不是永久音乐库，也没有固定 24 小时删除规则。

## 关闭窗口后 Bot 还在线，正常吗？

正常。关闭窗口释放 WebView2，保留托盘和后台服务。从托盘选择退出才会停止应用管理的 Bot 与 SSH。未保存表单可在同一次应用运行中重开窗口恢复；完全退出后不保留草稿。

Activity 有参与者时不因空闲自动结束；语音频道连续 60 秒无人仍会结束房间。仅使用 `/play` 时按设置的空闲时间退出。

## 移动软件、工具或换电脑后怎么办？

工具移动后需要重新选择并检查。备份个人资料时保留整个 `user-data/`，但凭据与 Windows 账户绑定，复制到另一台电脑或另一账户不代表能解密，需要重新配置。更新和卸载不会自动删除个人资料。

## 如何更新和反馈？

到 [本项目 Releases](https://github.com/Neon-Soda/Yachiyo-Jukebox/releases) 查看版本和附件，按 [下载指南](DOWNLOADS.md) 更新；当前没有自动更新器。

[提交 Issue](https://github.com/Neon-Soda/Yachiyo-Jukebox/issues) 时附上版本、Windows 版本、操作步骤、来源链接和界面错误提示。需要时手动导出诊断，审阅后再分享。不要上传 Token、Cookie、SSH 私钥或整个用户目录。
